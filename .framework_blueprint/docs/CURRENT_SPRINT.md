## 🛠️ Детальное Микро-ТЗ спринта

### Задача 1: `[Миграция базы данных и Доменный подпакет]`
* **Пакеты и файлы**: `backend/migrations/00000X_name.up.sql` (и `.down.sql`), `backend/internal/domain/<feature>/`
* **Требования**:
  - Создание таблицы с `id UUID PRIMARY KEY`, `created_at`, `updated_at`, внешними ключами и индексами.
  - В доменном подпакете `internal/domain/<feature>/` разделить код на логические файлы (`entity.go`, `errors.go`, `repository.go`), соблюдая лимит `<= 5–7 файлов` в пакете и `< 300–400 строк` в файле.
  - Доменная сущность с валидацией всех бизнес-инвариантов из раздела «Микро-решения» и 100% покрытием быстрыми юнит-тестами.

---

### Задача 2: `[Спецификация OpenAPI и Кодогенерация (Contract-First)]`
* **Файлы**: `backend/api/openapi/api.yaml`
* **Требования**:
  - Строгие схемы DTO запроса и ответа с ограничением длин строк, форматов и обязательных полей (`required`).
  - Описание эндпоинтов и всех кодов ответа (`200`, `201`, `400`, `401`, `403`, `404`, `429`, `500`).
  - Запуск кодогенерации (`make oapi`) для создания серверных интерфейсов и клиентских TypeScript-типов.

---

### Задача 3: `[Серверная реализация Use Cases, Адаптеров и DI в internal/app]`
* **Пакеты**: `backend/internal/application/<feature>/`, `backend/internal/infrastructure/postgres/<feature>repo/`, `backend/internal/infrastructure/http/<feature>handler/`, `backend/internal/app/`
* **Требования**:
  - Если сервису нужны данные из соседнего домена — объявить минимальный интерфейс в `internal/application/<feature>/ports.go` (никаких прямых импортов соседних подпакетов `application/*`).
  - Строгая проверка прав доступа (Tenant Isolation / RBAC) внутри сервисного слоя.
  - Централизованный маппинг доменных ошибок в HTTP-статусы без утечки внутренних SQL/системных ошибок.
  - Подключение нового сервиса и роута в `internal/app/` (`services.go`, `router.go`).
  - Юнит-тесты сервиса с моками и флагом `-race`.

---

### Задача 4 & 5: `[Клиентский интерфейс (Frontend)]`
* **Пакеты**: `frontend/src/features/<feature>/` (`components/`, `hooks/`, `types.ts`)
* **Требования**:
  - Сборка интерфейса **исключительно** из атомарных компонентов `src/shared/components/ui/` и семантических цветовых токенов Дизайн-паспорта.
  - Вынос всей логики запросов и состояния в кастомные хуки (`hooks/use[Feature].ts`), компоненты остаются тонкими.
  - Обязательная реализация 4 состояний: `Loading (Skeleton)`, `Error (с кнопкой повтора)`, `Empty State (с призывом к действию)`, `Success`.
  - Все файлы строго `< 300–400 строк`, в каждой папке `<= 5–7 файлов`.

### Чек-лист Безопасности (Security Gate):
- [ ] **Tenant Isolation / RBAC**: Проверено (в коде и E2E-тестом), что пользователь не может получить доступ к чужим ресурсам по ID (защита от IDOR).

- [ ] **Секреты и Ошибки**: В коде и логах нет чувствительных данных (паролей, токенов, `.env`), а `500 Internal Server Error` не раскрывает stack trace клиенту.
