# Frontend & Design Конвенции (`docs/conventions/frontend.md`)

> Этот документ определяет правила архитектуры интерфейса, структуру компонентов и **Дизайн-паспорт проекта**.
> Обязателен к прочтению субагентами роли `frontend_developer` и всеми инженерами клиентской части.

---

## 📁 1. Структура каталогов (Feature-Sliced + Лимит `<= 7 файлов в фиче`)

```text
frontend/src/
├── app/                     # Инициализация, глобальные провайдеры (QueryClient), темы, роутер
├── pages/                   # Тонкие страницы-контейнеры (до 100 строк, композиция виджетов и фич)
├── widgets/                 # Крупные композиционные блоки экрана (навигация, сайдбар, bento-панели)
├── features/                # Интерактивные фичи / пользовательские сценарии (auth, search, editor)
│   └── [feature_name]/
│       ├── components/      # Внутренние UI-компоненты фичи (<= 7 файлов, каждый < 300 строк)
│       ├── hooks/           # Кастомные хуки бизнес-логики и запросов (use[Feature].ts)
│       ├── types.ts         # Локальные типы фичи
│       └── utils.ts         # Чистые хелперы фичи
├── entities/                # Доменные UI-сущности (user, project, resource)
├── shared/
│   ├── components/ui/       # АТОМАРНЫЙ UI-KIT ПРОЕКТА (Button, Input, Card, Modal, Skeleton...)
│   ├── hooks/               # Универсальные хуки (useDebounce, useHotkeys, useMediaQuery)
│   ├── lib/                 # Утилиты форматирования, cn хелпер
│   └── api/                 # Сгенерированный клиент OpenAPI
└── tailwind.config.js       # Токены дизайн-системы и типографика
```

## 🎨 2. Дизайн-паспорт проекта (Заполняется на старте через `BOOTSTRAP.md`)

> **Закон для фронтенд-агентов**: Запрещено придумывать произвольный визуальный стиль на отдельных страницах. Весь интерфейс строится строго по параметрам дизайн-паспорта.

### 1. Визуальный архетип и референсы (Vibe)
* `[Например: Минималистичный инженерный SaaS в духе Linear / Stripe / Claude. Высокий контраст, тонкие рамки 1px, акцент на читаемости данных без визуального мусора]`
* **Базовая тема**: `[Dark Mode First / Light Mode / Системная]`

### 2. Семантические цветовые токены (Tailwind / CSS Variables)

> **ТАБУ**: Внутри `features/`, `widgets/` и `pages/` **строго запрещено** использовать сырые цвета Tailwind (`bg-blue-500`, `text-gray-400`, `bg-zinc-900`, `#1a2b3c`). Это проверяется автоматически через `make check-arch`. Используются **только** семантические переменные:

```css
:root {
  /* Поверхности и Холст */
  --bg-canvas: #...;            /* Базовый фон приложения */
  --bg-surface: #...;           /* Поверхность карточек, панелей, модалок */
  --border-subtle: #...;        /* Тонкие разделители строк и таблиц */

  /* Текст */
  --text-primary: #...;         /* Основной контрастный текст */
  --text-muted: #...;           /* Вторичный приглушенный текст, подписи */

  /* Акценты и интерактив */
  --accent-surface: #...;       /* Мягкая заливка фокусных элементов / ховеров */
  --accent-solid: #...;         /* Основной акцентный цвет (кнопки, чекбоксы) */
  --accent-solid-hover: #...;

  /* Статусы (опционально) */
  --status-success: #...;
  --status-warning: #...;
  --status-error: #...;
}
```

### 3. Геометрия, Сетка и Типографика
* **Скругления (Border Radius)**: карточки и модалки — `rounded-xl` (или `16px`), кнопки и инпуты — `rounded-lg` (или `8px-10px`).
* **Отступы**: кратные `4px/8px` (`gap-2`, `gap-4`, `gap-6`, `p-4`, `p-6`).
* **Типографика**:
  - Заголовки экранов: `[например: Newsreader / Inter Display]`.
  - Основной UI и формы: `[например: Geist Sans / Inter / Plus Jakarta Sans]`.
  - Моноширинный текст (числа, хоткеи, ID, код): `[например: JetBrains Mono]`.

## 🧩 3. Правило Атомарного UI-Kit (`src/shared/components/ui/`)

1. В **Фазе 0** создается базовый набор переиспользуемых компонентов в `src/shared/components/ui/`:
   `Button`, `Input`, `Select`, `Checkbox`, `Card`, `Badge`, `Modal`, `Skeleton`, `EmptyState`, `ErrorBanner`.
2. При разработке любой фичи в `src/features/*` субагенты **обязаны импортировать эти компоненты**, а не верстать кастомные `<button>` или `<input>` с нуля.
3. **4 обязательных состояния каждого экрана (Mandatory UI States)**:
   - `Loading`: аккуратный `Skeleton` из UI-Kit (без резких полноэкранных спиннеров).
   - `Error`: компонент `ErrorBanner` с понятным текстом и кнопкой «Повторить».
   - `Empty`: компонент `EmptyState` с иконкой, пояснением и кнопкой целевого действия.
   - `Success`: отображение данных с адаптивностью (`sm:`, `md:`, `lg:`).

## ⚡ 4. Управление состоянием (State Management)

* **Серверные данные**: **`TanStack Query v5`** (`@tanstack/react-query`).
  - Все сетевые запросы мутаций сопровождаются оптимистичным обновлением UI (`onMutate` $\rightarrow$ откат в `onError` $\rightarrow$ инвалидация в `onSettled`).
* **Клиентский UI-стейт**: **`Zustand`** (активные вкладки, локальные фильтры, туглы панелей). Redux и MobX не используются.
* **UI-компоненты**: сборка экранов строго на базе компонентов из `shared/components/ui/`.
