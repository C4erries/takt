### TASK-B20: Действие автоматизации «Вернуть в предыдущую колонку» (Return to Previous Column) {#task-b20}

🔲 **Статус**: В бэклоге · **Сложность**: M · **Бэкенд + фронтенд**

**Продуктовая цель**: Автоматический возврат задачи в ту колонку, где она находилась до переноса в «Готово» (при отмене выполнения задачи).

**Принятые решения**:
1. **Новое действие в DSL (`rule.go`)**: `ActionReturnToPreviousColumn = "return_to_previous_column"`.
2. **Логика поиска предыдущей колонки на бэкенде**:
   - Воркер/исполнитель правил анализирует историю `task_activities` (таблица `000015_task_activities`):

     - Извлечение `from_column_id` из `payload`.
   - **Fallback стратегия**:
     - Если колонка найдена и существует на текущей доске: переместить задачу в нее.
     - Если записи в истории нет или колонка была удалена: переместить в первую todo-колонку текущей доски (через `ProjectReader.GetFirstTodoColumn`).
     - Если доска/колонка недоступна: отправить задачу во «Входящие» (`column_id = NULL`).
3. **UI**: Добавить действие «Вернуть в предыдущую колонку» в селектор действий конструктора правил (`RuleBuilderSections.tsx`).

**Продуктовая цель**: Возможность запускать автоматизации не только при завершении задачи, но и при снятии отметки выполнения (отмене завершения).

**Принятые решения**:

### TASK-B22: Скоупы тегов в БД и API (Workspace-level vs Project-level) {#task-b22}

🔲 **Статус**: В бэклоге · **Сложность**: M · **Бэкенд (миграция + API)**

**Продуктовая цель**: Позволить командам создавать проектные теги, которые не засоряют глобальный список тегов других проектов.

**Принятые решения**:
1. **Схема БД (миграция 000016_tag_scopes)**:
   ```sql
   ALTER TABLE tags ADD COLUMN project_id UUID NULL REFERENCES projects(id) ON DELETE CASCADE;
   -- Уникальность имени тега внутри воркспейса с учетом проекта:
   DROP INDEX IF EXISTS idx_tags_workspace_name;
   CREATE UNIQUE INDEX idx_tags_workspace_project_name 
     ON tags(workspace_id, COALESCE(project_id, '00000000-0000-0000-0000-000000000000'), LOWER(name));
   CREATE INDEX idx_tags_project_id ON tags(project_id) WHERE project_id IS NOT NULL;
   ```
   - Если `project_id IS NULL` — тег глобальный на весь воркспейс.
   - Если `project_id IS NOT NULL` — тег доступен только в рамках указанного проекта.
2. **OpenAPI & Queries**:
   - Обновить DTO тега: добавить опциональное поле `projectId: UUID | null`.
   - `GET /workspaces/{wid}/tags?project_id=...`: если `project_id` передан, возвращает глобальные теги воркспейса + проектные теги этого проекта. Если не передан — возвращает все теги воркспейса.
   - `POST /workspaces/{wid}/tags`: принимает опциональный `projectId`.

**Файлы**:
- `backend/migrations/000016_tag_scopes.up.sql`
- `backend/queries/tasks.sql`
- `api/openapi/schemas/task.yaml`
- `backend/internal/domain/task/tag.go`
- `backend/internal/application/task/tags_usecases.go`
- `backend/internal/infrastructure/http/tasks_handler.go`
