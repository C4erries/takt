### TASK-B22: Скоупы тегов в БД и API (Workspace-level vs Project-level) {#task-b22}

🔲 **Статус**: В бэклоге · **Сложность**: M · **Бэкенд (миграция + API)**

**Продуктовая цель**: Позволить командам создавать проектные теги, которые не засоряют глобальный список тегов других проектов.

**Принятые решения**:
1. **Схема БД (миграция 000016_tag_scopes)**:
   ```sql
   ALTER TABLE tags ADD COLUMN project_id UUID NULL REFERENCES projects(id) ON DELETE CASCADE;
   DROP INDEX IF EXISTS idx_tags_workspace_name;
   CREATE UNIQUE INDEX idx_tags_workspace_project_name 
     ON tags(workspace_id, COALESCE(project_id, '00000000-0000-0000-0000-000000000000'), LOWER(name));
   CREATE INDEX idx_tags_project_id ON tags(project_id) WHERE project_id IS NOT NULL;
   ```
   - Если `project_id IS NULL` — тег глобальный на весь воркспейс.
   - Если `project_id IS NOT NULL` — тег доступен только в рамках указанного проекта.
2. **OpenAPI & Queries**:
   - `projectId: UUID | null` в схеме `Tag`.
   - `GET /workspaces/{wid}/tags?project_id=...`: возвращает глобальные теги воркспейса + проектные теги выбранного проекта.
   - `POST /workspaces/{wid}/tags`: принимает опциональный `projectId`.

**Файлы**:
- `backend/migrations/000016_tag_scopes.up.sql`
- `backend/queries/tasks.sql`
- `api/openapi/schemas/task.yaml`
- `backend/internal/domain/task/tag.go`
- `backend/internal/application/task/tags_usecases.go`
- `backend/internal/infrastructure/http/tasks_handler.go`

### TASK-B20: Действие «Вернуть в предыдущую колонку» (с fallback во Входящие доски) {#task-b20}

🔲 **Статус**: В бэклоге · **Сложность**: M · **Бэкенд + фронтенд**

**Продуктовая цель**: Автоматический возврат задачи в ту колонку, где она находилась до переноса в выполненные, при отмене выполнения.

**Принятые решения**:
1. Действие в DSL: `ActionReturnToPreviousColumn = "return_to_previous_column"`.
2. Поиск колонки в истории `task_activities` (`activity_type = 'column_moved'` -> `from_column_id`).
3. **Утвержденный Fallback**:
   - Возврат во **Входящие текущей доски** (колонка с флагом `is_inbox = true` на доске задачи).
   - Если такой колонки на доске нет — возврат в **общие Входящие воркспейса** (`column_id = NULL`, проект очищается при необходимости или сохраняется).
4. UI: отображение действия в конструкторе автоматизаций.

**Файлы**:
