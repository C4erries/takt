## 🧠 1. Аналитика и Зафиксированные микро-решения спринта (Режим «Штаб»)

* **Бизнес-цель**: Устранить бессмысленные и ломающие логику комбинации в Low-Code конструкторе (например, оператор «содержит» для времени в колонке или «заполнено» для булевого флага завершения) путем жесткой фильтрации операторов под контекст каждого поля. Снабдить условия и действия с тегами быстрым клиентским автокомплитом по существующим тегам воркспейса (с поиском по подстроке в реальном времени) и возможностью создавать новые теги в действии добавления.

* **Микро-решения спринта (Решения Штаба)**:
  - **D-065b-1 (Матрица допустимых операторов по полям условий)**:
    - `time_in_column_hours` (Время в колонке): `greater_than` («Больше чем»), `less_than` («Меньше чем»), `equals` («Ровно»). Исключены `contains`, `not_contains`, `in`, `is_empty`, `is_not_empty`.
    - `is_completed` (Завершена): `equals` («Равно»), `not_equals` («Не равно»). Исключены все текстовые и сравнительные операторы.
    - `priority` (Приоритет): `equals` («Равно»), `not_equals` («Не равно»), `in` («Один из»), `not_in` («Ни один из»).
    - `due_date_status` (Статус дедлайна): `equals` («Равно»), `not_equals` («Не равно»), `in` («Один из»).
    - `due_date` (Дедлайн): `equals` («Равно»), `greater_than` («Позже чем»), `less_than` («Раньше чем»), `is_not_empty` («Установлен»), `is_empty` («Не установлен»).
    - `tags` (Теги): `contains` («Содержит тег»), `not_contains` («Не содержит тег»), `in` («Один из»), `is_not_empty` («Есть любые теги»), `is_empty` («Без тегов»).
    - *Авто-коррекция*: При переключении поля условия, если текущий оператор отсутствует в списке допустимых для нового поля, он автоматически сбрасывается на первый валидный дефолт.
  - **D-065b-2 (Живой автокомплит тегов в условиях)**:
    - Список существующих тегов берется из `useWorkspaceTagsQuery(workspaceId)` без лишних запросов.
    - При вводе текста в инпут выпадает красивое меню подсказок с совпадениями по подстроке (без учета регистра).
    - Клик по подсказке подставляет выбранный тег.
    - При операторе `in` («Один из») теги добавляются в набор кликабельных чипов (мульти-теги).
  - **D-065b-3 (Умный селектор тегов в действиях Low-Code)**:
    - *Действие «Добавить тег» (`add_tag`)*:
      - Инпут с выпадающим списком подсказок существующих тегов воркспейса.
      - Если введенный текст не совпадает с существующими тегами, внизу подсказок отображается плашка: `✨ Создать тег "{query}"`.
    - *Действие «Удалить тег» (`remove_tag`)*:
      - Селектор строго из существующих тегов воркспейса с фильтрацией по вводимому тексту (создавать новые теги для удаления запрещено).
  - **D-065b-4 (Авто-привязка созданного правила к колонке)**:
    - Когда пользователь нажимает «+ Собрать своё правило» в модалке автоматизаций колонки, созданное правило автоматически сохраняется с `columnId: prefilledColumnId` и сразу появляется в списке кастомных правил этой колонки.
