## 🧠 1. Аналитика и Зафиксированные микро-решения спринта (Режим «Штаб»)

* **Бизнес-цель**: Дать пользователю возможность самостоятельно собирать произвольные правила автоматизации («КОГДА происходит событие $\rightarrow$ ЕСЛИ выполняются условия $\rightarrow$ ТО сделать действия») как для конкретной колонки, так и глобально для проектов/воркспейса, включая временные SLA-таймеры и ежедневные расписания.

* **Принятые продуктовые и технические решения (Согласовано с пользователем)**:
  - **D-062-1 (UX-парадигма: Линейный конструктор блочных предложений — Вариант А)**:
    - Конструктор проектируется в стиле «Sentence Builder» (как в Linear / Zapier / Notion): вертикальная карточная цепочка «КОГДА (Триггер) $\rightarrow$ ЕСЛИ (Условия) $\rightarrow$ ТО (Действия)».
    - Без перегруженных нодовых диаграмм и графов. Простой, ясный, чистый Washi-интерфейс.
  - **D-062-2 (Полный скоуп триггеров: событийные + временные)**:
    - *Событийные триггеры*:
      1. `task_entered_column` — задача перемещена или создана в колонке.
      2. `task_completed_in_column` — задача отмечена выполненной внутри колонки.
      3. `task_field_changed` — изменение приоритета, дедлайна или статуса.
    - *Временные триггеры*:
      4. `column_sla_timer` — задача находится в колонке дольше N часов/дней (Aging / SLA).
      5. `scheduled_sweep` — запуск по расписанию для задач в колонке (Daily sweep).
  - **D-062-3 (Две точки входа в интерфейсе)**:
    - *Точечная (колоночная)*: в меню действий колонки `...` в `ColumnAutomationsModal` добавляется кнопка «+ Собрать своё правило» с предзаполненным триггером текущей колонки.
    - *Глобальная*: пункт навигации «⚡ Автоматизации» в левом сайдбаре (Хаб автоматизаций), где отображается реестр всех активных правил воркспейса/проектов с тумблерами Вкл/Выкл, удалением и кнопкой создания глобальных правил.
  - **D-062-4 (DSL, хранение и исполнение правил — ADR-0004)**:
    - Формат DSL зафиксирован в [ADR-0004](file:///home/pavel/projects/takt/docs/decisions/0004-low-code-automations-dsl.md): объект `rule_definition` (JSONB) со схемами `trigger`, `conditions` (логика AND) и `actions` (последовательно).
    - Миграция БД: добавление поля `rule_definition JSONB NOT NULL DEFAULT '{}'::jsonb` в таблицу `automations`.
    - Исполнение событийных правил: через существующий `EventBus` и `listener.go` с оценкой условий (`RuleEvaluator`).
    - Исполнение временных правил: фоновый легковесный тикер-воркер в бэкенде с проверкой таймеров колонок.
    - Защита `Cycle Guard`: лимит до 3 каскадных вызовов на первичное действие.
