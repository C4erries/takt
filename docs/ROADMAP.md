# Дорожная карта проекта Takt (`ROADMAP.md`)

> Общий стратегический план развития проекта Takt.
> Каждая фаза представляет собой self-contained майлстоун с работающим продуктовым результатом и 100% прохождением архитектурного и тестового контроля.
>
> **Легенда статусов**: 🔲 Planned (Запланировано) · 🔵 In Progress (В работе) · ✅ Done (Завершено) · ⏸️ Paused (На паузе)

---

## Фаза 0: Инженерный фундамент, Архитектурный линтер и UI-Kit «Soft Editorial GTD» 🔲
> **Цель**: Развернуть каркас монорепозитория в Docker Compose, настроить автоматический архитектурный контроль `make check-arch`, мультифайловый OpenAPI и создать атомарный UI-Kit по Дизайн-паспорту японской канцелярии.

- [ ] Инициализация структуры монорепозитория (`backend/`, `frontend/`, `deploy/`, `tests/`, `scripts/`, `docs/`, `api/`).
- [ ] Базовый Go-сервис на **Echo v4** с точкой сборки зависимостей `backend/internal/infrastructure/container/` (`main.go` < 50 строк).
- [ ] Настройка пула БД `pgxpool`, транзактора через `context.Context` и конфигурации `sqlc.yaml`.
- [ ] Настройка скрипта **`scripts/check_arch.sh` и команды `make check-arch`** (лимит строк < 400, лимит файлов в доменном пакете <= 7, запрет сырых цветов Tailwind, чистота слоев DDD).
- [ ] Мультифайловый OpenAPI манифест (`api/openapi/*`), сборка через `@redocly/cli` и генерация через `oapi-codegen`.
- [ ] Базовая инфраструктура: `docker-compose.yml` (PostgreSQL 16, Backend, Frontend, Nginx reverse-proxy) и `Makefile`.
- [ ] Базовый атомарный **UI-Kit в `frontend/src/shared/components/ui/`** (`Button`, `Input`, `Checkbox` 18px круглый, `Card`, `Badge` капсульный, `Modal`, `Skeleton`, `EmptyState`, `ErrorBanner`) на токенах Washi/Matcha.
- [ ] Каркас E2E-тестирования на Python (`pytest` + `httpx`) в `tests/` с фикстурами API-клиента.

---

## Фаза 1: Авторизация, Персональный Workspace и Захват в Inbox (Quick Capture) 🔲
> **Цель**: Полный цикл Zero-friction онбординга (регистрация $\rightarrow$ вход в личный воркспейс), быстрый сбор входящих мыслей/задач в Inbox с J/K навигацией.

- [ ] Доменный пакет `internal/domain/workspace` и таблица `workspaces` (автосоздание `personal` воркспейса).
- [ ] Авторизация (JWT в HTTP-only cookies / Header), хеширование паролей, Echo middleware аутентификации и Tenant Isolation.
- [ ] Доменный пакет `internal/domain/task` и хранилище задач Inbox (`project_id` и `column_id` nullable).
- [ ] Быстрый захват задач (Quick Task Capture): хоткей добавления, сохранение заголовка и заметок.
- [ ] Фронтенд-каркас «Surface-on-Canvas» (3 колонки): левый сайдбар навигации + центральный лист Washi с разлиновкой задач.
- [ ] Пружинная J/K клавиатурная навигация по строкам задач и переключение круглого чекбокса выполнения.
- [ ] Сквозные Pytest E2E-тесты: регистрация, создание задач в Inbox, отметка выполнения, защита от неавторизованного доступа.

---

## Фаза 2: Проекты, Канбан-доски, Фокус «Сегодня» и Пресеты Автоматизаций 🔲
> **Цель**: Организация задач по проектам и колонкам статусов, фокусный вид «Focus of the Day», правая Bento-панель (инспектор задачи + матричный календарь) и запуск фонового движка автоматизаций v1.

- [ ] Доменные пакеты `internal/domain/project` (проекты, доски, упорядоченные колонки со статусами).
- [ ] Канбан-доска с drag-and-drop карточек на `@dnd-kit/core` + переключение в плоский вид Списка (List View).
- [ ] Фокус-вид «Сегодня / Focus of the Day» с отбором задач по дедлайну или приоритету фокуса.
- [ ] Правая панель Bento: инспектор задачи (Markdown-описание, капсульные теги контекста) + матричный календарь с 1px границами.
- [ ] Движок событий `internal/domain/events` (`EventBus`) и доменный пакет `internal/domain/automation`.
- [ ] Реализация 3 пресетных правил с тумблерами Вкл/Выкл в интерфейсе:
  1. *Inbox Zero*: Задаче назначен проект/срок $\rightarrow$ автоперемещение из Inbox.
  2. *Done & Archive*: Чекбокс отмечен $\rightarrow$ автоперенос в колонку «Done» и дата завершения.
  3. *Auto-Focus*: Срок задачи наступил «Сегодня» $\rightarrow$ автоперевод в активный статус / фокус.
- [ ] E2E-тесты на Pytest: полный цикл перемещения карточек, срабатывание автоматизаций при смене чекбокса/даты.

## Фаза 3: Совместная работа (Shared Workspaces) и Расширенная организация 🔲
> **Цель**: Возможность совместного ведения проектов с коллегами, разделение ролей Owner/Member, фильтрация и поиск.

- [ ] Создание общих воркспейсов (`type = shared`) и приглашение участников по ссылке/email.
- [ ] Ролевая проверка: `Owner` (управление воркспейсом, правилами и участниками) vs `Member` (работа с задачами).
- [ ] Фильтрация по тегам контекста (`@дом`, `@работа`, `20 мин`), поиск по задачам, сортировка.
- [ ] Оптимизация производительности: кэширование и оптимистичные мутации TanStack Query.
- [ ] Pytest E2E-тесты проверки прав доступа между участниками и строгой защиты от IDOR.

---

## Фаза 4: Конструктор автоматизаций v2 (Hybrid / Low-Code Engine) и Интеграции 🔲
> **Цель**: Расширение движка автоматизаций до полноценного конструктора (с поддержкой скриптовых/low-code выражений), фоновые таймеры и внешние интеграции.

- [ ] Проектирование конструктора правил: поддержка произвольных триггеров, цепочек условий и действий (с заложенной идеей гибридного low-code / скриптового описания).
- [ ] Подключение внешних адаптеров (Webhooks, Telegram-уведомления).
- [ ] Периодические задачи и фоновый тикер времени (проверка дедлайнов).
- [ ] Экспорт данных (JSON, Markdown) и интеграция с календарями.
