# ADR-0001: Выбор начального архитектурного стека, принципов DDD и мультифайлового OpenAPI

* **Дата**: `2026-10-14`
* **Статус**: `Accepted`
* **Инициатор / Автор**: `Pavel (Founder) & Lead AI Architect (Co-Founder)`
* **Затрагиваемые подсистемы / пакеты**: `backend/*`, `frontend/*`, `api/openapi/*`, `deploy/*`, `tests/*`

---

## 🎯 1. Контекст и Проблема (Context & Problem Statement)

Проект **Takt** создается как персонально-ориентированный таск-трекер и командная система продуктивности с канбан-досками и фоновыми автоматизациями рабочих процессов. Требуется выбрать фундамент архитектуры и технологический стек, который:
1. Обеспечивает исключительную скорость работы интерфейса и минимальное время отклика API (< 20-50ms).
2. Надежно поддерживает хранение доменных сущностей (воркспейсы, проекты, задачи) и декларативных JSONB-правил автоматизаций.
3. Имеет строгую модульность с защитой контекста AI-агентов (файлы `< 350-400` строк, пакеты `<= 7` файлов, разделение через `ports.go`).
4. Поддерживает Contract-First разработку без раздувания гигантских OpenAPI-файлов.
5. Реализует эстетику *Editorial Tech / Humanist Minimalism* (дизайн японской канцелярии Midori MD / Hobonichi + Claude).

---

## 🔍 2. Рассмотренные варианты (Considered Options)

### Вариант 1: Go + Echo + sqlc/pgx + React/TS + Multi-file OpenAPI + Pytest E2E (Выбран)
* **Суть подхода**: 
  - Бэкенд на Go 1.23+ с роутером Echo v4. Слой данных строится на `sqlc` + `pgx/v5` с транзакциями через `context.Context` (`Transactor`).
  - Домен изолирован по подпакетам (`workspace`, `project`, `task`, `automation`, `events`), интерфейсы объявляются строго на стороне потребителя (`ports.go`).
  - Фронтенд на React 18/19 + Vite + Tailwind CSS + TanStack Query + Zustand.
  - OpenAPI 3.0 декомпозирован на `paths/` и `schemas/`, собирается через `@redocly/cli`.
  - Черный ящик E2E-тестов на Python (`pytest` + `httpx`) в изолированном контейнере.
* **Плюсы (+)**:
  - Максимальная производительность и минимальное потребление ресурсов Go.
  - `sqlc` валидирует чистый SQL во время компиляции — ноль runtime-ошибок маппинга и полное отсутствие оверхеда тяжелых ORM (GORM).
  - Агенты не путаются в мультифайловом OpenAPI и изолированных подпакетах до 7 файлов.
  - Независимый E2E-контроль на Pytest покрывает сквозные сценарии быстрее и чище.
* **Минусы (-)**:
  - Необходимость шага сборки контракта (`redocly bundle`) перед запуском `oapi-codegen`.

### Вариант 2: Node.js (NestJS / Fastify) + Prisma + Full No-Code UI
* **Суть подхода**: Единый язык TypeScript на клиенте и сервере, Prisma ORM.
* **Плюсы (+)**: Единая типизация между клиентом и сервером.
* **Минусы (-)**: Prisma генерирует медленный тяжелый SQL, холодный старт контейнеров, повышенное потребление памяти, отсутствие жесткой защиты слоев DDD.

---

## 🏆 3. Принятое решение и Обоснование (Decision Outcome)

**Выбран Вариант 1**:
Утвержден стек: **Go 1.23+ (Echo v4, sqlc, pgx/v5, Transactor via context)** + **React/TypeScript (Vite, Tailwind, TanStack Query, Zustand)** + **PostgreSQL 16** + **Multi-file OpenAPI 3.0** + **Pytest E2E** + **Nginx reverse proxy**.

**Обоснование**:
Решение обеспечивает строгую типизацию, надежность ACID-транзакций, модульность и максимальную продуктивность AI-агентов благодаря отсутствию «магических» тяжелых ORM и четкому разделению доменных подпакетов.

---

## 📈 4. Последствия, Безопасность и План внедрения (Consequences)

### Положительные последствия:
- Строгая проверка архитектуры скриптом `make check-arch`.
- Детерминированная кодогенерация типов через `sqlc` и `oapi-codegen`.
- Тактильный интерфейс без визуального шума на семантических токенах.
- Возможность эволюции движка автоматизаций в v2 (low-code/scriptable) без переписывания бэкенда.

### Влияние на безопасность:
- Полная изоляция арендаторов (Tenant Isolation) на уровне `workspace_id`.
- Параметризованный SQL исключает риск SQL Injection.
- Обезличивание внутренних ошибок сервера (`500`).

### План внедрения:
1. Зафиксировать структуру директорий монорепозитория в `CURRENT_SPRINT.md` (Фаза 0).
2. Подготовить конфиги `sqlc.yaml`, `scripts/check_arch.sh`, `Makefile` и базовый атомарный UI-Kit.
