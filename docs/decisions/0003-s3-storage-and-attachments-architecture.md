# ADR-0003: Архитектура S3-хранилища, вложений и перманентных Content URL

* **Дата**: `2026-10-15`
* **Статус**: `Accepted`
* **Инициатор / Автор**: `Lead Orchestrator / CTO & User`
* **Затрагиваемые подсистемы / пакеты**: `docker-compose.yml`, `backend/internal/infrastructure/storage/s3`, `backend/internal/domain/attachment`, `backend/internal/application/attachment`, `backend/internal/infrastructure/http`, `api/openapi/*`, `frontend/src/widgets/task-inspector`

---

## 🎯 1. Контекст и Проблема (Context & Problem Statement)

Пользователям необходимо прикреплять к задачам файлы, скриншоты и документы (включая вставку картинок из буфера обмена `Ctrl+V` прямо в Markdown-заметки).
Возникают ключевые архитектурные развилки:
1. **Какое хранилище использовать**: хранение BLOB в PostgreSQL приводит к раздуванию базы и деградации производительности бэкапов. Необходимо S3-совместимое объектное хранилище.
2. **Как организовать загрузку**: прямая загрузка через Presigned PUT URLs против проксирования через бэкенд (`multipart/form-data`).
3. **Как организовать доступ к файлам**: временные Presigned GET ссылки с ограниченным TTL (1–2 часа) приводят к тому, что ссылки на картинки, вставленные в Markdown-текст заметок, со временем «протухают» и превращаются в битые изображения.
4. **Безопасность и изоляция (Tenant Isolation)**: публичный бакет S3 недопустим, так как нарушает приватность данных между воркспейсами.

---

## 🔍 2. Рассмотренные варианты (Considered Options)

### Вариант 1: Direct Upload и Presigned GET URLs
* **Суть подхода**: Клиент запрашивает у бэкенда Presigned PUT URL, заливает файл напрямую в S3, а для чтения генерируются временные ссылки с подписью AWS SigV4.
* **Плюсы (+)**:
  - Минимальная нагрузка на I/O бэкенда.
* **Минусы (-)**:
  - В Docker Compose окружении возникает проблема сетевой маршрутизации S3 (изнутри контейнеров MinIO доступен как `minio:9000`, а из браузера — как `localhost:9000`).
  - Прямые Presigned GET ссылки в Markdown-заметках неизбежно протухают при истечении TTL подписи, ломая отображение картинок в заметках.

### Вариант 2 (Принятый): Backend Multipart Proxy Upload + Стабильный перманентный Content URL
* **Суть подхода**:
  - Загрузка идет через эндпоинт бэкенда `POST /api/v1/workspaces/{workspace_id}/tasks/{task_id}/attachments` (`multipart/form-data`). Бэкенд валидирует права доступа, стримит байты в S3 (`PutObject`) и создает метаданные в PostgreSQL.
  - Чтение и рендеринг картинок осуществляются по стабильному перманентному эндпоинту:
    `GET /api/v1/workspaces/{workspace_id}/attachments/{attachment_id}/content` (с заголовками `Content-Type`, `Cache-Control` и поддержкой query-параметра `?download=true`).
* **Плюсы (+)**:
  - Ссылки на картинки в Markdown (`![Screenshot](/api/v1/.../content)`) никогда не протухают.
  - Полная прозрачность для Docker-окружения и локального MinIO, отсутствие проблем с CORS и сетевыми именами хостов.
  - Единый надежный контур проверки прав (Tenant Isolation) — чужой пользователь не получит доступ к файлу без валидного JWT и членства в воркспейсе.
  - Простота настройки S3-провайдера (MinIO в dev, AWS S3 / Cloudflare R2 / Ceph в prod).
* **Минусы (-)**:
  - Файловый I/O транзитно проходит через бэкенд (для лимита 50 МБ на текущем этапе нагрузка полностью несущественна).

---

## 🏆 3. Принятое решение и Обоснование (Decision Outcome)

**Выбран Вариант 2**: Бэкенд-проксирование загрузки файлов (`multipart/form-data`) и перманентный защищенный Content URL для чтения и встраивания медиа в Markdown, с локальным MinIO в `docker-compose.yml` и настраиваемым лимитом размера (по умолчанию 50 МБ).

**Обоснование**:
Решение обеспечивает целостность пользовательского опыта (картинки в заметках сохраняют работоспособность неограниченное время), строго соблюдает Tenant Isolation и исключает проблемы с сетевой адресацией S3-хостов в локальной и контейнерной разработке.

---

## 📈 4. Последствия, Безопасность и План внедрения (Consequences)

### Положительные последствия:
- Единый интерфейс работы с любыми S3-провайдерами через официальный `aws-sdk-go-v2`.
- Надежная вставка скриншотов из буфера обмена (`Ctrl+V`) в Markdown без поломки изображений в будущем.
- Изоляция данных воркспейсов: доступ к бинарному контенту контролируется через стандартные middleware авторизации Takt.

### Компромиссы и Влияние на безопасность:
- Бэкенд стримит бинарные потоки с ограничением по размеру (`MAX_ATTACHMENT_SIZE_BYTES`, дефолт 50 МБ), не загружая весь файл целиком в оперативную память.
- Имена файлов санитизируются для предотвращения Path Traversal и инъекций заголовков `Content-Disposition`.
- В БД таблица `attachments` связана внешними ключами с `tasks` и `workspaces` с каскадным удалением (`ON DELETE CASCADE`).

### План внедрения:
1. Добавление сервиса `minio` и `minio_init` (для создания бакета `takt-attachments`) в `docker-compose.yml`.
2. Шаг 1 (Контракты и Чистый Домен): Миграция `000007_attachments.up.sql`, sqlc-запросы, спецификация OpenAPI (`paths/attachments.yaml`, `schemas/attachment.yaml`), `make generate`, домен `internal/domain/attachment`.
3. Шаг 2 (Use Cases & Инфраструктура): S3-адаптер в `internal/infrastructure/storage/s3`, Use Cases в `internal/application/attachment`, Echo HTTP-хендлеры, связывание в `container`, галерея вложений и `Ctrl+V` перехват во фронтенде, Pytest E2E-тесты.
