# Архив спринтов (`Sprints Archive`)

> В этом каталоге хранятся **отчеты обо всех завершенных спринтах проекта**, включая принятые в рамках этих спринтов продуктовые микро-решения и метрики качества.
>
> **Правило экономии контекста для AI-агентов (Шаг 0)**:
> Агентам **не нужно** читать все файлы отчетов подряд. На Шаге 0 агент просматривает только **Индексный реестр завершенных спринтов** ниже, чтобы понимать историю развития проекта, и открывает конкретный файл `sprint-X.Y.Z.md` только если нужно узнать детали прошлых микро-решений по конкретной фиче.

## 🏷️ Иерархия версий, этапов и нумерации спринтов

В проекте Takt принята 3-уровневая семантическая иерархия планирования:

```text
Фаза / Версия (Phase X)
   └── Этап / Майлстоун (Stage X.Y)
          └── Спринт разработки / фиксов (Sprint X.Y.Z)
```

1. **Фаза / Глобальная версия (`Phase X`)**:
   - `Фаза 0` — Инженерный фундамент, Архитектурный линтер и UI-Kit.
   - `Фаза 1` — Core MVP v1 (Personal Inbox, Проекты, Канбан, Фокус «Сегодня», Пресеты автоматизаций).
   - `Фаза 2` — Shared Workspaces и командная работа.
   - `Фаза 3` — Конструктор автоматизаций v2 (Hybrid/Low-code) и интеграции.
2. **Этап / Функциональный блок (`Stage X.Y`)**:
   - Логический блок функциональности внутри фазы (например, `0.1` — Фундамент и UI-Kit; `1.1` — Авторизация и Personal Workspace; `1.2` — Доски и задачи; `1.3` — Движок автоматизаций).
3. **Спринт (`Sprint X.Y.Z`)**:
   - Атомарная итерация работы. 
   - `X.Y.1` — основной спринт реализации функционала этапа `X.Y`.
   - `X.Y.2`, `X.Y.3`... — стабилизационные спринты (багфиксы, полировка UI, разгребание техдолга/бэклога) перед переходом к следующему этапу.

## 📦 Регламент архивации спринта

Когда все пункты Definition of Done (DoD) в `docs/CURRENT_SPRINT.md` выполнены и подтверждены независимым запуском `make check-arch`, модульных и E2E-тестов:
1. Создается файл `docs/sprints/sprint-X.Y.Z.md` (по шаблону `template.md`).
2. В него переносятся:
   * **Принятые микро-решения спринта (Product & Tech Micro-Decisions)** — чтобы история локальных бизнес-правил никогда не терялась;
   * Список созданных/обновленных доменных подпакетов и реализованных фич;
   * Итоговые метрики качества (`make check-arch`, `make test`, `npm run build`, `make test-e2e`, проверки безопасности).
3. В таблицу **Индексного реестра** выше добавляется новая строка со ссылкой на `sprint-X.Y.Z.md`.
4. В `docs/ROADMAP.md` и `docs/PROJECT_CONTEXT.md` (Карта пакетов) актуализируются статусы и новые подпакеты.
5. Файл `docs/CURRENT_SPRINT.md` очищается и переводится в **Фазу А (Режим «Штаб»)** для проектирования следующего спринта (`X.Y.(Z+1)` или `X.(Y+1).1`).
