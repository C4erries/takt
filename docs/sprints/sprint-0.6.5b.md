## 🎯 Цели и Результаты спринта

1. **Контекстная матрица допустимых операторов по полям условий (`FIELD_OPERATORS_MAP`)**:
   - `time_in_column_hours` (Время в колонке): доступны только `Больше чем` (`>`), `Меньше чем` (`<`) и `Равно` (`=`). Полностью устранены бессмысленные операторы вроде «содержит», «заполнено», «пусто», «один из».
   - `is_completed` (Завершена): строго `Равно` и `Не равно` с кнопками «Да (выполнена)» / «Нет (в работе)».
   - `priority` (Приоритет): `Равно`, `Не равно`, `Один из`, `Ни один из`.
   - `due_date_status` (Статус дедлайна): `Равно`, `Не равно`, `Один из`.
   - `due_date` (Дедлайн): `Равно`, `Позже чем`, `Раньше чем`, `Установлен`, `Не установлен`.
   - `tags` (Теги): `Содержит тег`, `Не содержит тег`, `Один из`, `Есть любые теги`, `Без тегов`.
   - **Авто-коррекция операторов**: при смене поля в условии, если старый оператор отсутствует в списке допустимых для нового поля, он автоматически сбрасывается на дефолтный валидный.

2. **Живой клиентский автокомплит тегов в условиях**:
   - Реализован быстрый поиск по существующим тегам воркспейса (`useWorkspaceTagsQuery`) без лишних запросов к бэкенду.
   - При операторах `contains` / `not_contains`: выпадающее меню подсказок с совпадениями по подстроке и кликабельной вставкой.
   - При операторе `in` («Один из»): мульти-выбор с удобными чипами `[tag ✕]` и добавлением через инпут поиска.

3. **Умный селектор тегов в действиях Low-Code**:
   - **Действие `add_tag` (Добавить тег)**: живой поиск по существующим тегам воркспейса. Если введенного тега еще нет — внизу списка появляется интерактивная плашка `✨ Создать тег "{текст}"`.
   - **Действие `remove_tag` (Удалить тег)**: выбор строго из существующих тегов воркспейса (создание новых отключено).

4. **Авто-привязка созданного правила к колонке (D-065b-4)**:
   - В [useRuleBuilder.ts](file:///home/pavel/projects/takt/frontend/src/features/automations/useRuleBuilder.ts): при создании правила из окна колонки выставляется `effectiveColumnId = prefilledColumnId || triggerColumnId || null`.
   - В SQL-запросе [automations.sql](file:///home/pavel/projects/takt/backend/queries/automations.sql) и репозитории [automation_repository.go](file:///home/pavel/projects/takt/backend/internal/infrastructure/repository/automation_repository.go): добавлен `column_id` в `INSERT INTO automations`.
   - Теперь при создании правила через «Собрать своё правило» в колонке оно сразу привязывается к колонке и отображается в блоке «Кастомные правила для этой колонки».
