## 🧠 1. Зафиксированные микро-решения спринта (Preserved Micro-Decisions)

* **Бизнес-цель**: Устранение узких мест эргономики:
  1. В конструкторе автоматизаций: при скоупе правила «На доску» триггер расписания (`scheduled_sweep`) не требует выбора конкретной колонки и по умолчанию охватывает все колонки доски;
  2. Селекторы целевой доски и колонки структурированы по проектам и доскам вместо плоского списка;
  3. Перенос менеджера тегов из узкого поповера в полноценный экран `TagManagerView` в `MainSheet` (аналогично «Архиву» и «Автоматизациям»).
* **Ключевые продуктовые правила и Edge Cases**:
  - `scheduled_sweep` для доски: если `column_id` не указан, воркер автоматически производит периодическую обработку всех колонок доски (с сохранением ADR-0008 batch SQL fast path для каждой колонки).
  - Иерархическая группировка:
    - Селектор целевой доски: `<optgroup label="Проект: {projectName}">` → доски проекта.
    - Селектор целевой колонки: `<optgroup label="{projectName} → {boardName}">` → колонки доски.
    - В `MoveTaskModal`: фильтрация с учетом названия проекта.
  - Полноэкранный рабочий стол тегов `TagManagerView`:
    - Просторная сетка карточек тегов с фильтром, счетчиком связанных задач (`formatTaskCount`), инлайн-переименованием (карандаш / Enter / Escape), 12-цветной палитрой в 1 клик и безопасным удалением.
    - Кнопка удаления всех неиспользуемых тегов с бейджем количества.
    - Роутинг `/tags` и переход из `Sidebar.tsx` с активной подсветкой пункта навигации.
* **Локальные технические решения**:
  - `ProjectReader` расширен методом `ListColumnIDsByBoard(ctx, boardID)`.
  - Воркер автоматизаций получил внедрение `ProjectReader`.
  - Все файлы строго выдержаны в лимите < 400 строк (все файлы < 380 строк), в пакетах <= 7 файлов.

## 🎯 2. Ключевые результаты и Затронутые подпакеты
