# Архив спринтов (`Sprints Archive`)

> В этом каталоге хранятся **отчеты обо всех завершенных спринтов проекта**, включая принятые в рамках этих спринтов продуктовые микро-решения и метрики качества.
>
> **Правило экономии контекста для AI-агентов (Шаг 0)**:
> Агентам **не нужно** читать все файлы отчетов подряд. На Шаге 0 агент просматривает только **Индексный реестр завершенных спринтов** ниже, чтобы понимать историю развития проекта, и открывает конкретный файл `sprint-X.Y.md` только если нужно узнать детали прошлых микро-решений по конкретной фиче.

## 📦 Регламент архивации спринта

Когда все пункты Definition of Done (DoD) в `docs/CURRENT_SPRINT.md` выполнены и подтверждены независимым запуском `make check-arch`, модульных и E2E-тестов:
1. Создается файл `docs/sprints/sprint-X.Y.md` (по шаблону `template.md`).
2. В него переносятся:
   * **Принятые микро-решения спринта (Product & Tech Micro-Decisions)** — чтобы история локальных бизнес-правил никогда не терялась;
   * Список созданных/обновленных доменных подпакетов и реализованных фич;
   * Итоговые метрики качества (`make check-arch`, `make test`, `npm run build`, `make test-e2e`, проверки безопасности).
3. В таблицу **Индексного реестра** выше добавляется новая строка со ссылкой на `sprint-X.Y.md`.
4. В `docs/ROADMAP.md` и `docs/PROJECT_CONTEXT.md` (Карта пакетов) актуализируются статусы и новые подпакеты.
5. Файл `docs/CURRENT_SPRINT.md` очищается и переводится в **Фазу А (Режим «Штаб»)** для проектирования следующего спринта (`X.Y+1`).
